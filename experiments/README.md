# Замеры

Каждый скрипт отвечает на **один** вопрос и печатает ответ таблицей
с доверительными интервалами. В рантайм отсюда ничего не импортируется;
пакет исключён из образа.

Запуск — модулем, из корня проекта. Именно модулем, а не по пути к файлу:
скриптам нужен корень на `sys.path`, чтобы видеть `measurement`, `agent`
и остальное.

```bash
python -m experiments.retrieval
```

Общая обвязка — пути, парный бутстрэп, колонки метрик — в `measurement.py`
в корне. Результаты и рассуждения — в `_research/EVOLUTION.md`.

## Что чем проверено

| Скрипт | Вопрос | Чем кончилось |
|---|---|---|
| `retrieval.py` | какая стратегия поиска лучше: dense, гибрид, реранкинг | перевод запроса окупается, реранкинг отклонён |
| `tokenizer.py` | не из-за токенизатора ли BM25 не даёт прироста | нет; заодно выяснилось, что BM25 вредит |
| `bm25_weight.py` | есть ли вес, при котором BM25 помогает и не мешает | нет такого веса; гибрид выключен |
| `run_noise.py` | сколько в сквозной дельте от приёма, а сколько от шума прогона | у BM25 влияние на ответ не доказано |
| `chunking.py` | как размер чанка влияет на качество поиска | при равном объёме текста крупная нарезка лучше мелкой |
| `chunking_end_to_end.py` | доходит ли выигрыш нарезки до ответа | нет; миграция не окупается |
| `qrels_bias.py` | не меряет ли разметка сама себя | две трети выигрыша реранкинга были согласием модели с собой |
| `judge_noise.py` | какую разницу судья вообще способен различить | порог 0.010 для correctness, 0.004 для relevancy |
| `judge_bias.py` | не завышает ли судья оценку собственным ответам | завышает на 12-19 пунктов |
| `dataset_scope.py` | много ли в датасете вопросов не про питание | треть, но на метриках это не сказывается |
| `grade.py` | насколько строго отбирать найденные фрагменты | строгий критерий принят |
| `answer_prompt.py` | промпт генерации: боевой против кандидата | требование полноты принято, «состав доказательств» отклонён |
| `measure_solver.py` | не ухудшился ли подбор рациона | регрессионный гейт, гоняется на каждую правку солвера |

Четыре замера из тринадцати закончились «ничего не делать», а один —
«убрать то, что уже работает». Это не неудача: каждый из отклонённых
приёмов выглядел улучшением и был бы принят без замера — один ценой 23%
времени ответа, другой ценой пересборки всей разметки релевантности.
А гибридный поиск, наоборот, держался с самого начала проекта как
«вреда не доказано», пока замер не доказал вред.

## Как устроен честный замер

Правила выведены из собственных ошибок, каждая описана в журнале.

**Критерий приёмки задаётся до прогона**, константой в скрипте. Иначе,
увидев цифры, критерий подгоняется сам собой. Вердикт скрипты печатают
сами — решать после факта нечего.

**Порог различимости важнее значимости.** Парный бутстрэп меряет шум
выборки и ничего не знает о нестабильности судьи. Интервал уже 0.010
не доказывает ничего, даже когда бутстрэп говорит «значимо».

**Прирост метрик поиска — не результат.** Дважды измерено, что значимое
улучшение поиска не доходит до ответа. Доводи до `correctness`.

**«Вреда не доказано» — не «вреда нет».** Замер, отвечающий на вопрос
«даёт ли прирост», отрицательным ответом закрывает только этот вопрос.
BM25 держался на такой формулировке, пока его не спросили иначе.

**У прогона агента свой шум.** Метрики генерации из прогонов, сделанных
в разное время, нельзя сравнивать напрямую: те же настройки дважды дали
correctness 0.860 и 0.876. Нужна контрольная группа — вопросы, где обе
конфигурации отдали в генерацию одинаковый контекст, то есть одни и те же
чанки **в одном и том же порядке**. Считает `run_noise.py`.

**Если перед поиском стоит модель, метрики поиска шумят так же.** Узел
`rewrite` переписывает запрос вызовом LLM, поэтому сквозные precision
и recall из разных прогонов несравнимы наравне с correctness. Контрольная
группа тут не спасает: она определена через совпадение выдачи, и дельта
поиска в ней ноль по построению. Решать по поиску — только замерами
на кэшированных запросах, образец `bm25_weight.py`.

**Судью надо проверять независимым судьёй**, если он приходится роднёй
проверяемому приёму. Реранкер и разметчик пула — одна модель с почти
одинаковой задачей; под родственной разметкой выигрыш был втрое больше
настоящего.

**Выдачи сохраняются** в `_research/dataset/experiments_retrieval_runs.json`,
чтобы пересчитать метрики под другой разметкой без новых вызовов модели.

## Сколько это стоит

Замеры обращаются к API. Полный цикл — несколько долларов; для итераций
хватает 80 вопросов вместо 210 (`--n 80`). Самые дорогие — те, что гоняют
агента целиком: `answer_prompt`, `chunking_end_to_end`, `grade`.
