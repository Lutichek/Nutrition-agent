# Аудит пищевого ограничения

Утечки здесь всегда тихие: план собирается, проверки КБЖУ проходят,
а в тарелке свиные желудки. Поэтому аудит — это ЗАМЕР «сколько блюд
с запретом проходит фильтр», а не чтение кода.

## Порядок

1. **Замер утечки** — скриптом, из корня проекта:

   ```bash
   PYTHONIOENCODING=utf-8 python .claude/skills/nutrition-dev/scripts/leak_scan.py gluten
   ```

   Печатает: во что раскрылось ограничение, проверяется ли оно по составу,
   как сузился подбор по ролям, известные скрытые источники
   (`KNOWN_HIDDEN`) и составные ингредиенты оставшихся блюд. Список
   составных смотри ЦЕЛИКОМ: редкая утечка — 1–2 блюда внизу.

   Гипотезу проверяй `--hidden "regex"`, конкретное блюдо — `--dish "Croutons"`.
   `KNOWN_HIDDEN` — подсказка, а не полный список: в первом аудите глютена
   он нашёл 5 блюд из 90, остальное всплыло при просмотре составных.

2. **Обратная сторона — что фильтр выкидывает ЗРЯ:**

   ```bash
   PYTHONIOENCODING=utf-8 python .claude/skills/nutrition-dev/scripts/leak_scan.py gluten --removed
   ```

   Показывает отсечённые блюда по проходу (название / раздел / состав)
   и слову, которое сработало. Так нашлось, что подстроки `pasta`,
   `noodles`, `tortilla` в разделе уносили при глютене единственную
   гречку, пшено, киноа и кукурузные чипсы — 46 безглютеновых блюд.
   Это не аллерген в тарелке, но «хочу гречку» тогда объясняется как
   «снято ограничением» — то есть ложью.

3. **Синонимы ограничения.** Модель называет категорию не всегда
   ключом из `CATEGORIES`. Скрипт печатает, если слово не категория
   и не синоним (`ALIASES`) — тогда оно ищется буквально. Опасный
   случай: `"gluten-free"` буквально уносит именно безглютеновое и
   переворачивает ограничение, `"celiac"` не отсекает ничего. Проверь
   естественные формулировки категории (диагноз, «без X», «X-free»).

4. **Разделить находки на три группы** и не смешивать их:
   - **явная утечка** — продукт точно содержит запрещённое (терияки —
     пшеница, «Breakfast meat» — бекон). Чинится в коде;
   - **спорное** — зависит от человека (овёс при целиакии, «мясо
     неизвестно какое» при халяле). Выносится человеку на решение
     с числом блюд: это его здоровье и его вера, а не выбор кода;
   - **ложное** — слово совпало, продукта нет (coconut milk для лактозы,
     ginger ale для глютена). Чинится исключением, НЕ убиранием слова.

5. **Где чинить** (`restrictions.py`):
   - синоним категории → слово в `CATEGORIES[...]` (не забудь `s?`-формы —
     их даёт `_english_forms`, проверь);
   - ложное совпадение у молочного → `NOT_DAIRY` (только соседние слова:
     «rice … milk» через запятую — это молоко);
   - скрытый источник без рецептуры → слово в категорию с комментарием,
     ПОЧЕМУ (у продукта SR нет рецептуры). Догадку «наверное, содержит»
     без рецептуры не вписывать: «Hot dog, NFS» оказался говяжьим.
   - тип блюда («мучное», «сладости», «жареное») по составу не
     проверяется — `TYPE_CATEGORIES`. «Не ем мучное» = хлеб и выпечка,
     не загуститель.

6. **Тест на наблюдавшийся случай** в `tests/test_restrictions.py`:
   конкретное блюдо из замера не проходит `_filter_catalog`, и рядом —
   блюдо, которое ДОЛЖНО остаться (булочка для хот-дога при `pork`,
   гречка при `gluten`). Убедись, что тест падает на старом коде
   (`git stash`).

7. **Утечка в ПЛАНАХ, а не только в каталоге.** Число блюд в пуле
   не говорит, как часто человек их получит. Собери дни с этим
   ограничением (профили `measure_solver.PROFILES` + `exclude`, 40 сидов)
   и посчитай, в скольких днях есть утечка — до и после правки.
   Первый аудит глютена: 90 блюд в пуле, утечка в 26% дней.

8. **Цена правки** — `measure_solver` (каталог сузился):

   ```bash
   python -m experiments.measure_solver --save до      # ДО правки
   python -m experiments.measure_solver --against до   # после
   ```

   ⚠️ Штатный замер видит только ограничения из своих `PROFILES`
   (сейчас pork, sweets, flour, lactose). Правку другого ограничения он
   НЕ заметит — сначала добавь профиль с ним в `PROFILES` и `EXTRA_SEEDS`
   (40 сидов) и сними точку отсчёта уже на новом протоколе.

   Узкий пул чувствителен к пути поиска — смотри «худшее откл. ккал»,
   а не только среднее. Ухудшение по профилю с ограничениями разбирай:
   было ли в старых планах запрещённое? Если да — прежняя точность
   держалась на нарушении, это записывается в EVOLUTION.md.

## Отчёт

Человеку — коротко: сколько блюд протекало (по группам), что починено,
что вынесено на его решение и с какими числами, что показал замер.
